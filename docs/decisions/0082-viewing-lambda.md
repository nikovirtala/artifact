# 0082. Viewing Lambda

Status: Accepted (M10)

## Context

The viewing plane serves artifacts, the gallery and the login routes on `<view>` and `*.<view>` through CloudFront, from one Lambda function URL origin (the distribution is a later ADR). The v1 viewing app (0056) already serves pages over any `HostPolicy` (0053) and any raw-target hook (0055); what the Lambda adds is how it learns the viewer's host, which cookies it lets in, and which responses CloudFront may cache.

- A function URL with `AuthType` `AWS_IAM` behind origin access control accepts only requests CloudFront signs for this distribution; an unsigned call is rejected ([Restrict access to an AWS Lambda function URL origin](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-restricting-access-to-lambda.html); [Control access to Lambda function URLs](https://docs.aws.amazon.com/lambda/latest/dg/urls-auth.html)) (V7, F4). The event has the API Gateway payload 2.0 shape: `rawPath`, `rawQueryString`, lowercase `headers`, a separate `cookies` array, and response `cookies` become `Set-Cookie` ([Invoking Lambda function URLs](https://docs.aws.amazon.com/lambda/latest/dg/urls-invocation.html)) (F4).
- For a function URL origin the viewer's `Host` is replaced by the origin's, so the edge copies it to `x-artifact-host` (0080; [Managed origin request policies](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/using-managed-origin-request-policies.html)) (V7).
- CloudFront caches error responses for 10 seconds unless told otherwise, and for 2xx with `no-cache`/`no-store` and a minimum TTL of 0 it respects the headers ([Control how long CloudFront caches errors](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/custom-error-pages-expiration.html); [Expiration](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/Expiration.html)) (F7).
- `src/http/reload.ts` reads `./reload-client.js` relative to its module at load, and the only live-reload transport today is local SSE; AWS live reload is M11.

## Decision

- **Handler** `createViewingHandler({service, viewDomain, loadKeys, oidc, owners, fetch, now})` in `src/runtime/handlers/viewing.ts`, per event:
  1. `x-artifact-host` (read case-insensitively) must be present and accepted by `DomainHostPolicy`, else 403 `forbidden: unexpected Host header` (`no-store`) without running the app. The header is trusted only because the function URL is `AWS_IAM` + OAC.
  2. The event's `headers.host` and `requestContext.domainName` become that host (hono/aws-lambda builds the URL from `domainName`).
  3. Cookies: on the main host's three login paths only `__Host-artifact_login` is kept (`keepCookies`, array and `Cookie` header); everywhere else every cookie is removed (`stripCookies`). The edge already did both; this is the third layer.
  4. The outer app, with `csp` undefined (there is no `ARTIFACT_CSP` on AWS, so artifact pages keep 0025's default of no CSP and the three security headers; the gallery keeps `GALLERY_CSP`): host guard and traversal guard on the raw target (400 before any route), the login sub-app (0081), `/__artifact/events` → 404 (no SSE on Lambda), `/a` and `/a/*` → 404 on the main host (**path mode is off on AWS**: it would serve every artifact on the gallery origin and break per-artifact storage isolation), the outer `onError`/`notFound` with the security headers, then `createViewingApp` with `noopEvents` and subdomain isolation.
  5. **Cache-Control by class:** a response that sets its own keeps it — pinned 200 `public, max-age=31536000, immutable`, current 200 and `reload.js` `no-cache`, gallery, `/__artifact/version`, redirects and login `no-store`. Anything else (404, 400, 403, 405, 500) gets `no-store`. So only pinned files are cacheable, and current URLs are revalidated on every request and never stale after a publish. The distribution's error-caching TTL of 0 is the second layer (F7).
  6. One access line after the response: `artifact view {"requestId","method","host","path","status","cookies","ms"}` with `path` = `rawPath` truncated to 256 characters and `cookies` = the count received before filtering. The query is never logged (the callback's holds the code and state), nor any header or cookie value.
- **Reload before M11:** `/__artifact/reload.js` serves the existing client with `{transport: "none", viewSuffix: ".<view>", pathMode: false}`. `none` has no entry in the client's transport table, so the page opens no `EventSource` and makes no request (0058's inert unknown transport). The only `src/http/` change is widening `ReloadTransport` to `"sse" | "none"`; local bytes and behaviour are unchanged.
- **`reload-client.js` ships next to `index.mjs`** in the viewing asset, copied byte for byte by `pnpm bundle`, because `reload.ts` reads it at module load (`/var/task/reload-client.js`); without it init fails with ENOENT and every request is a 502. No esbuild text loader and no change to `reload.ts`.
- **Environment** (`parseViewingEnv`; errors name the variable, never a value; an invalid environment fails init): `ARTIFACT_BUCKET`, `ARTIFACT_VIEW_DOMAIN` (`DomainHostPolicy`-valid), `ARTIFACT_SESSION_SECRET_ARN` (a Secrets Manager ARN), `ARTIFACT_OIDC_ISSUER`, `ARTIFACT_OIDC_AUTHORIZE_URL`, `ARTIFACT_OIDC_TOKEN_URL`, `ARTIFACT_OIDC_LOGOUT_URL` (`https:` URLs), `ARTIFACT_OIDC_CLIENT_ID` (`[A-Za-z0-9_+-]{1,128}`) and `ARTIFACT_OWNERS` (a JSON array of 1–50 lowercase emails). The construct keeps the sum of names and values at most 3500 bytes, counting tokens at fixed upper bounds, inside Lambda's 4 KB.
- **Role (built with the construct): read-only.** `s3:GetObject` on the objects, `s3:ListBucket` on the bucket, `secretsmanager:GetSecretValue` on the session secret, and log writes to its own group. **Deviation** from the plan's "S3 GetObject + ListBucket only": login lives in this Lambda and signing a session needs the key. It has no write permission of any kind.
- **Concurrency (built with the construct):** reserved 20 by default, which needs an account limit of at least 120 because Lambda keeps 100 unreserved (F8); optional provisioned concurrency goes on a `live` alias, and since AWS does not say whether the function URL's `FunctionArn` is alias-qualified (F12), the construct then adds its own two invoke permissions on the alias ARN next to CDK's.
- **Bundle:** `dist/assets/viewing/` with no MCP SDK, zod, node-server, `src/mcp/`, API or control app; the runtime's `@aws-sdk/*` stays external (0068).

## Consequences

The v1 viewing code runs unchanged on AWS; only the event adapter, the cookie filter, the cache-class rule and the inert reload config are new. A request that bypasses CloudFront cannot reach the code, and one that reaches it without a valid `x-artifact-host` gets 403. The session cookie, which the edge already removed, cannot reach the app, its errors or its logs. Pages carry no live reload until M11 replaces `none` with the AppSync transport. The viewing role can read the session key, which is the price of signing in the same function.
