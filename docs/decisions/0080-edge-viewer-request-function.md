# 0080. Edge viewer-request function

Status: Accepted (M10)

## Context

Pages on the view domain are behind login from the first deploy. The check has to run before CloudFront's cache, so a cached page is never served to a visitor without a session, and it has to hand the viewer's host to a Lambda function URL origin whose own `Host` CloudFront replaces. The plan puts this in a CloudFront Function with one KeyValueStore. What that runtime allows shapes the code:

- A `cloudfront-js-2.0` function reads its KeyValueStore with `cf.kvs()` and `await kvsHandle.get(key)`, which throws on a missing key; AWS recommends sequential `await` over promise combinators ([Helper methods for key value stores](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/functions-custom-methods.html)). KeyValueStore needs runtime 2.0 ([Restrictions on CloudFront Functions](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/cloudfront-function-restrictions.html)). `crypto.createHmac("sha256", key)` with a `base64url` digest is available ([JavaScript runtime 2.0 features](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/functions-javascript-runtime-20.html)); AWS's `kvs-jwt-verify` sample does the same verification ([aws-samples/amazon-cloudfront-functions](https://github.com/aws-samples/amazon-cloudfront-functions/tree/main/kvs-jwt-verify)) (V6).
- The same runtime page: `async` arguments and closures are not supported, there are no timers, `process`, `eval` or network, `console.log` takes one argument, and `crypto.timingSafeEqual` is not listed (F3). A function is at most 10 KB, with one KeyValueStore per function ([Quotas](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/cloudfront-limits.html)) (V6, F1).
- In a viewer-request event `Host` is read-only, header names added by the function must be lowercase, and cookies are in a `cookies` object apart from `headers` ([Restrictions on all edge functions](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/edge-function-restrictions-all.html); [CloudFront Functions event structure](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/functions-event-structure.html)). A header the function sets can be in the cache key and forwarded by an origin request policy ([forwarding the host header](https://repost.aws/knowledge-center/configure-cloudfront-to-forward-headers)), and a function-generated response bypasses the cache and the origin ([Determine function purpose](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/function-code-choose-purpose.html)) (V7).

## Decision

- **Source** `src/runtime/edge/viewer-request.js`, plain JS. Line 1 is `import cf from "cloudfront";`, line 2 `import crypto from "crypto";`, line 3 empty (Biome's import organiser requires it), and the line `const VIEW_DOMAIN = "__ARTIFACT_VIEW_DOMAIN__";` occurs exactly once. `src/cdk/edge.ts` `renderEdgeFunction(source, viewDomain)` replaces that line with the JSON-quoted view domain at synth and throws unless the placeholder occurs exactly once as a whole line and the result is under 10,240 bytes. The function holds no token: `cf.kvs()` without an id uses the function's one associated store. `pnpm bundle` checks lines 1–3 and the placeholder and copies the file byte for byte to `dist/assets/edge/viewer-request.js`; it is not an esbuild entry.
- **Lint:** a `biome.json` override for `src/runtime/edge/**` turns off `useNodejsImportProtocol` (otherwise `biome check --write` would rewrite `"crypto"` to `"node:crypto"`, which the runtime rejects) and `noUnusedVariables` (CloudFront calls the unexported `handler`). There are no inline suppressions.
- **Shape:** `handler` is the only `async` function and holds the only `await`; every helper is synchronous, and there are no arrow functions. The signature compare is a hand-written XOR over the 43 characters, as in the AWS sample.
- **Logic**, per request:
  1. **Host:** lowercase, drop `:443`; the view domain itself or exactly one 26-character Crockford ULID label under it — the rules of `DomainHostPolicy.classify` (0053). Anything else (other ports, IPs, nested labels, a trailing dot, an empty Host) → 403 `forbidden: unexpected Host header`.
  2. **Login passthrough:** on the main host only, `/__artifact/login`, `/__artifact/callback` and `/__artifact/logout` go to the origin with every cookie removed except `__Host-artifact_login`, and with `x-artifact-host` set.
  3. **Session:** the `__Secure-artifact_session` cookie must be well formed (0078) before the store is asked for its `kid`; a missing key or a store error fails closed; then `exp > now` and the HMAC.
  4. **No valid session:** a navigation — `GET` with `sec-fetch-mode: navigate`, or with no `sec-fetch-mode` and an `accept` containing `text/html` — gets 302 to `https://<view>/__artifact/login?return=<the viewer's URL>`, with the query rebuilt in CloudFront's key order (one pair per `multiValue` entry, `name=` for an empty value). Everything else, including `HEAD`, gets 401 `unauthorized`.
  5. **Valid session:** `cookies` becomes `{}` and `x-artifact-host` is set to the normalised host, overwriting any value the client sent.
  Function-generated responses are `text/plain; charset=utf-8` with `Cache-Control: no-store`.
- **Tests** run the shipped file: `test/support/edge-vm.ts` reads `dist/assets/edge/viewer-request.js`, renders it with `renderEdgeFunction`, swaps only the two import lines for fakes (a `crypto` shim over `node:crypto`, a fake KeyValueStore) and runs it in `node:vm` without `process`, timers, `require` or `fetch`, with a one-argument `console.log` and a fixed clock. The edge test consumes the shared session vectors (0078); `edge-host-parity.test.ts` checks the host verdict against `DomainHostPolicy` on a table and a fast-check property; a static scan rejects timers, `process.`, `eval`, `new Function`, `require(`, `timingSafeEqual`, arrows and any `async` function but `handler`.

## Consequences

Unauthenticated requests never reach the cache or the origin, and the session cookie never leaves the edge on any behaviour; the cache and origin request policies (cookies none) and the viewing Lambda's own strip are further layers. The origin can trust `x-artifact-host` only because its function URL accepts nothing but CloudFront's signed requests (OAC, later ADR). The view domain must be a literal at synth, because it is substituted into the code. A Host rule change must be made in both `DomainHostPolicy` and the edge function; the parity test fails until they agree.
